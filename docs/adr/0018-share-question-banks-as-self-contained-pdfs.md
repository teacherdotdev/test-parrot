# Share Question Banks as self-contained PDFs

A Question Bank File will be an ordinary self-contained PDF representing one complete, non-empty Question Bank, separate from Exam PDF and DOCX Export Artifacts. Its pages will be a complete teacher-readable preview derived from one authoritative, versioned Question Bank Record attached as `pdfcx.json` with MIME type `application/json`, `/Desc` `pdf-canonical-extraction`, and `AFRelationship` `Source`. This keeps the file easy to inspect and share while ensuring Test Parrot never has to reconstruct its own structured content through OCR or PDF page parsing.

The format begins at `0.1.0` while unreleased and will be specified by a published JSON Schema plus prose semantics. It will use a format-owned semantic rich-text model rather than IndexedDB records, ProseMirror JSON, Exam export models, or Layout Plans. The record contains canonical Question Content and Question Metadata, optional teacher-entered bank description, author, and license, package-local ordinal identifiers, safe hyperlinks, and each referenced Media Asset exactly once as original base64 bytes identified by SHA-256. PDF preview images may duplicate those bytes because PDF image objects are renderer-oriented, unstable under rewriting, and cannot reliably preserve the original assets needed for import.

Export will construct and validate the record first, render the complete preview from that same record, and attach the exact serialized record. It will not create Question Bank export history or alter the bank. The preview will identify itself as a teacher Question Bank containing answers and warn that rewriting the PDF may remove its import data.

Import will accept the record from either carrier: a Question Bank File, from which exactly one attachment identified by `pdf-canonical-extraction` is read, or a standalone `application/json` file that is itself that record. The two paths differ only in how the record bytes are obtained — every rule that follows applies identically to both, and a record whose format is not `test-parrot/question-bank`, or whose exact format version has no implemented parser or migration, is rejected either way. A file dropped anywhere in the application enters the same inspection and confirmation flow as one chosen through the import dialog. It will validate schema, supported features, semantic relationships, safe URLs, media hashes and decoded properties, and bounded resource limits before showing a record-derived confirmation. Any unsupported required feature, malformed Question, missing or unreferenced Media Asset, ambiguous attachment, or validation failure rejects the whole file without local changes. A successful import atomically creates one new independent Question Bank with fresh local bank, Question, and choice identities while retaining content-addressed Media Asset hashes; it never merges, replaces, creates an Exam, or changes a Working Copy. Unknown optional fields are ignored and discarded rather than preserved as opaque data.
